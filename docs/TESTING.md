## 检查层级

| 层级 | 覆盖内容 | 运行环境 |
| --- | --- | --- |
| 核心 | 金额、时间、解析、重复依据、选择和导入规划 | Kotlin/JVM |

## 原生环境

专用 AVD 名称为 LocalLedger_API35，API35、x86_64、en-US、360×800dp、480dpi、字体 100%、三键导航。全部账目、商户、交易号和报表为合成数据。

```powershell
python scripts/run_native_checks.py --serial emulator-5580 --adb <ADB完整路径>
```

脚本检查设备 serial、AVD 名称、qemu 标记和 API 后安装 APK。默认执行更新界面 1 项、通用界面 24 项、容量 1 项、服务与通知 1 项。`--group update|ui|capacity|runtime` 选择单独场景，`--skip-build` 使用已构建产物。

界面检查覆盖明暗、大字体、横屏、短窗口、输入法、分类、账户、语言和悬浮操作；新增网格/列表偏好、16:10 平板、折叠前后尺寸与选中账目保留，并核对手机旋转后保持竖屏、月份/年份预设、月份区间草稿与校验。合成铰链避让通过本地布局检查验证。通知检查通过真实系统节点操作暂停、继续、快捷录入与划走，再从桌面打开应用核对恢复。容量检查使用独立的一万条账目和来源样本。

脚本保留 APK 哈希、JUnit 结果、截图和系统状态。结束时恢复显示、应用语言、权限与服务设置，关闭并删除专用测试数据库。结果位于 `artifacts/validation/` 或明确指定的输出目录。

## 真机记录

正式签名覆盖升级使用单独的 `scripts/run_upgrade_checks.py`，仍仅允许 LocalLedger_API35。该测试从原签名 APK 直接覆盖更新，比较全部数据库、偏好、文件探针、UID 和权限，拒绝旧证书回退后再次核对数据。步骤和参数见 [SIGNING.md](SIGNING.md)。正式升级后的模拟器不能用普通旧签名调试包覆盖；常规界面检查与升级检查应使用各自明确的测试前状态。

更新逻辑由合成响应验证双源并发、单源失败、全部失败、超时、空发行列表、数字版本排序、草稿／预发行过滤、链接边界、响应体限制、24 小时节流、手动检查和取消。原生更新界面检查两个同版本发行入口、加载状态、失败反馈、自动检测开关、深色及 200% 字号。真实平台 API 的匿名访问另存返回状态，不向仓库发布测试 Release。

设备命令使用明确 serial，权限按完整包名和组件核对。已有交易详情用于识别与弹窗检查，确认保存、余额与重启读回分别记录。导入先检查预览和映射，再由设备持有人确认。

验证记录包含版本、设备环境、具体场景、结果和证据文件。构建结果说明产物生成；系统交互由原生和真机结果补充。
