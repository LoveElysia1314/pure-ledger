# 从其他账本迁移数据

纯净记账可以导入符合下述结构的 XLSX 工作簿，以及本软件导出的 ZIP 数据包。从其他记账软件迁移时，先将原始导出转换为 XLSX，再在手机上预览、核对并确认导入。

CSV、旧版 XLS、PDF、截图、任意 JSON 和其他软件的 ZIP 备份不能直接导入。修改文件后缀不会转换格式。本文与[合成字段示例](../examples/import/synthetic-example.json)可一并交给 AI，作为转换目标；示例 JSON 本身不是导入文件。

## XLSX 的三张工作表

工作表必须分别命名为“支出”“收入”“转账”。三张表都要存在；没有某类交易时，保留该表的表头即可。

第 1 行是表头，不加封面、标题或合并单元格。以下列名必须完整保留，暂时不用的列也不能删除。列顺序可以调整，列名不能重复；支出和收入的“时间、分类、金额、账户”均使用各自的完整列名。

### 支出

```text
所属账本	支出时间	支出分类	支出金额	支出账户	备注	账单图片	记录时间	记录方式	退款总额	待报销	报销金额	报销入账账户	报销时间
```

### 收入

```text
所属账本	收入时间	收入分类	收入金额	收入账户	备注	账单图片	记录时间	记录方式	退款总额
```

### 转账

```text
所属账本	转账时间	转账金额	转出账户	转入账户	转账手续费	优惠	备注	账单图片	记录时间	记录方式
```

## 字段怎么填写

| 字段 | 规则 |
| --- | --- |
| 所属账本 | 每行必填，名称不超过 100 字。来源没有账本时，先确定统一的迁移账本名 |
| 支出时间／收入时间／转账时间 | 必填文本，如 `2026-01-02 12:00` 或 `2026-01-02 12:00:00`，按北京时间解释 |
| 记录时间 | 同样必填。来源没有创建时间时，可在转换约定中明确用交易时间填充，并在转换说明中记录这一处理 |
| 支出金额／收入金额 | 以元填写非负金额，建议两位小数，如 `18.50`。收支方向由工作表表达，不再写负号 |
| 转账金额 | 必须大于零，表示转出账户扣除的金额。转入金额为“转账金额－转账手续费＋优惠” |
| 转账手续费、优惠、退款总额、报销金额 | 非负金额，可留空，空值按零处理 |
| 分类、账户 | 支出和收入可留空；转账必须填写不同的转出、转入账户。已知名称建议统一去除前后空格，不超过 100 字 |
| 备注 | 保留原文和换行，不超过 10,000 字。迁移商户、交易对象时可写入“商户：…；原备注：…” |
| 记录方式 | 可留空；填写时仅接受“智能记账、语音记账、手动记账、周期记账、模板记账、快速记账、自动记账”之一 |
| 待报销 | 可填“是”“否”或留空，不能使用 Excel 布尔值 |
| 报销时间 | 可留空；填写时采用上述日期文本格式 |
| 账单图片 | 可留空，也可保留来源中的文字或链接；不会自动下载或恢复图片附件 |

金额不能使用科学计数法、负数或需要舍入才能精确到分的值。例如 `1.001` 会报错，不能擅自改成 `1.00`。所有日期建议存为文本；仅把 Excel 数字日期的显示样式改成日期，单元格内部仍可能是序列值，无法按本文规则读取。公式必须先转换为普通值，错误值和布尔单元格不能导入。

文件需在 20 MiB 以内，每张表最多 50,000 行数据。来源较大时可按不重叠的期间拆分，保留一份完整原始导出供核对。

## 会迁移什么

导入会建立或匹配同名账本、全局账户及对应收支类型的分类，写入金额、时间、备注、转账账户、手续费和优惠，并保留原始列用于来源核对。其他列可以作为附加资料保留，但不会自动变成界面中的专用字段。

当前 XLSX 导入没有独立的商户映射列，商户和交易对象应合并到备注，以便在账单列表和详情中查看。新增“交易对象”列只能保留原始资料，不能替代备注中的可见信息。

退款、待报销及报销信息会保存在原始资料中，**不会自动生成关联退款、报销流水或净支出计算**。信用卡还款、退款、报销、分摊和借贷应先确认来源含义，再决定记作收支还是转账；不要仅凭金额正负推断。

当前金额模型使用人民币整数分。来源含外币时，应先明确汇率、换算日期和保留原币信息的方式，不能直接把外币数值当作人民币，也不能由 AI 猜测汇率。

## 余额、重复与冲突

导入预览显示新增、跳过、冲突、收支金额和转账笔数。名称映射由文件中的账本、分类及账户名决定，需要改名时先修改转换文件再重新预览。

“导入账单影响账户余额”默认关闭。迁移已有历史时，可先只导入明细，再将账户余额校准为原账本当前余额；如果选择让历史账单参与余额计算，应从明确的期初余额出发核对，避免重复计算。新建账户的余额可能仍标记为未知。

重复判断依据规范化后的交易内容及同内容出现次数，不依据文件名。再次导入同一份文件会跳过已有记录；两笔相似交易不应由 AI 擅自合并。修改备注或附加列可能改变判重结果；来源位置相同而内容不同的行会提示冲突，确认含义后再决定是否保留两份。

存在无效行时不能确认导入；导入写入采用事务，失败会回滚。建议先转换少量有代表性的支出、收入和转账，核对预览及保存结果，再迁移全部数据。全部导入后按月份核对笔数、收入、支出和账户余额，并主动导出一份 ZIP 留存。

## 可复制给 AI 的转换要求

```text
请把我提供的其他记账软件导出文件，转换为纯净记账可导入的 XLSX。
以本文和 examples/import/synthetic-example.json 为格式依据。

1. 先列出来源字段到目标字段的映射、缺失字段和含义不明确的交易；
   对币种、转账扣款／到账额、退款、报销及借贷提出必要的问题。
2. 生成“支出”“收入”“转账”三张表；没有数据的表也保留完整表头。
   表头名称逐字对应本文，所有表头第 1 行开始，无合并单元格、公式或布尔值。
3. 金额用十进制元，精确到分，不静默舍入；日期用北京时间文本。
   不编造记录时间、账户、分类、交易号或汇率；任何填充值都写入转换说明。
4. 保留每一笔原始交易、备注及稳定来源标识，不擅自去重、合并或删掉失败行。
   商户和交易对象合并到备注，其他需要保留的原字段可另设附加列。
5. 明确转账金额是转出额，到账额＝转账金额－手续费＋优惠，避免手续费重复扣除。
   原文件的余额不伪装成收支；退款／报销不自动推导为本软件的关联流水。
6. 交付 XLSX、字段映射与异常清单，并按月列出原文件及转换文件的笔数、
   收入、支出、转账金额核对结果。说明未迁移的数据和原因，不隐瞒差异。
```

如果使用联网 AI，先检查原文件中的姓名、商户、账户、交易号和备注是否适合上传；可先提供脱敏的小样本确认映射，再在本机处理完整文件。

## 本软件 ZIP 数据包

ZIP 用于本软件导出的结构化账务数据迁移，可读取 v1–v5，当前导出 v5。包内包含账本、账户、分类、账单及相关引用。设置偏好和实际附件文件不在完整迁移范围内，图片链接不等于图片备份。

从其他软件迁入时优先采用上述 XLSX；不要将 CSV 或任意 JSON 压缩成 ZIP，也不要让 AI 在未核对引用和格式版本的情况下改写本软件 ZIP。
